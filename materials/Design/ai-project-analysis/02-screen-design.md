# AIプロジェクト分析 — 画面設計

> ステータス: **未実装・レビュー案**
> 対象: ProjNexus 案件詳細「開発」タブ（`detailTab=tasks`）
> 基準日時: **2026-09-14 10:00 JST**

本書は、LLM APIを利用する「プロジェクト進捗のAI要約＋リスク抽出」の画面仕様を、実装前にレビューできる状態へ固定するための資料である。添付の静的HTMLは見た目と状態遷移を確認するサンプルであり、API通信、認証操作、DB更新は行わない。

## 1. 配置とスコープ

### 1.1 配置

- 既存ルート: `GET /projects/{project}?detailTab=tasks`
- 既存タブ名: **開発**
- 挿入位置: 開発タブの「工数サマリー／進捗」直下、「タスク一覧」直前
- 対象案件: `status=approved` の案件
- MVPではAI専用タブを追加しない。進捗の根拠となるタスクと同じ画面内に置き、既存のタブ・URL状態管理への影響を最小化する。

既存実装では `resources/js/Pages/Projects/Show.tsx` の開発タブが1096行付近から始まり、進捗サマリーが1200行付近で終わる。この直後を統合点とする。AIカード自体はページへ直書きせず、独立したReactコンポーネントとして実装する。

### 1.2 画面上の情報階層

```text
案件ヘッダー（案件名／approved／案件ID）
└─ 詳細タブ
   └─ 開発
      ├─ 工数サマリー
      ├─ 進捗（完了率）
      ├─ AIプロジェクト分析カード  ← 今回の追加
      │  ├─ 生成操作・鮮度
      │  ├─ システム判定（期限超過）
      │  ├─ AI要約
      │  ├─ AIリスク
      │  ├─ AIによる次の確認事項
      │  └─ 週次報告下書き
      └─ タスク一覧
```

## 2. 閲覧・生成権限

UIの表示制御は補助であり、認可の正本はLaravel側とする。フロントエンドはLaravelから渡される `initialAiAnalysis` と `aiGeneration: { allowed, unavailableReason }` を表示に反映し、ロール名だけで独自判定しない。案件自体の閲覧可否は既存のProject Policyと案件詳細ルートで先に確定する。

| 利用者・条件 | 保存済み結果の閲覧 | 新規生成／再生成 |
|---|:---:|:---:|
| 本部管理者かつ案件の`view`権限あり | 可 | 可 |
| 案件と同部門の部門管理者かつ`view`権限あり | 可 | 可 |
| 起票者かつ`view`権限あり | 可 | 可 |
| 主担当かつ`view`権限あり | 可 | 可 |
| 同部門だが上記に該当しない利用者 | 可 | 不可（閲覧のみ） |
| 案件の`view`権限なし | 不可 | 不可 |
| 未承認案件 | 不可 | 不可 |

画面案では「権限なし」を、案件自体は閲覧できるがAI生成権限だけがない**閲覧専用状態**として表現する。案件の`view`権限がない場合は案件詳細そのものへ到達させない。

## 3. 判定責任の分離

「システムが事実として算出した内容」と「LLMが生成した内容」を同じ見た目で混在させない。

| 表示内容 | 判定主体 | 画面ラベル | 補足 |
|---|---|---|---|
| 完了率 | Laravel | システム集計 | `closed件数 ÷ 全タスク件数`。平均進捗率ではない |
| 期限超過タスク | Laravel | システム判定 | `due_date < 基準日` かつ `status != closed` |
| 期限超過日数 | Laravel | システム判定 | JSTの基準日との差。LLMに計算させない |
| 現在の進捗要約 | LLM | AI生成 | 入力された現況だけを要約 |
| リスクと推奨対応 | LLM | AI生成 | 確定事項ではなく、確認候補として提示 |
| 次に確認すべき事項 | LLM | AI生成 | 質問形式で提示 |
| 週次報告文 | LLM | AI生成・下書き | 前週比較や今週実績を根拠なしに断定しない |

カード内では、期限超過一覧を青系の「システム判定」ブロック、LLM出力をパープル系の「AI生成」ブロックとして視覚的に分ける。どちらも色だけでなく文字ラベルとアイコンで識別する。

## 4. 外部送信する情報

画面の「送信データ」詳細で利用者が確認できるようにする。

### 4.1 LLM APIへ送信する

- 案件名
- タスク名
- タスクのステータス・進捗率
- タスクの期限
- 見積工数・実績工数
- 案件の予算額・実績額

### 4.2 LLM APIへ送信しない

- 案件の目的・概要など自由記述本文
- タスク説明など自由記述本文
- コメント
- 氏名列（担当者・確認者・起票者等）
- メールアドレス
- 添付ファイル名・内容

### 4.3 利用者への注意

案件名・タスク名は業務上必要なため送信対象とする。タイトル自体に機密情報や個人情報が含まれている場合、それを自動的に検知・除去できる保証はない。生成ボタンの近くにこの注意を常時確認できる`details`要素として配置する。

## 5. カード構成

### 5.1 ヘッダー

- アイコン＋「AIプロジェクト分析」
- 「未実装レビュー案」バッジ（静的モックのみ）
- 最新結果の生成日時
- 鮮度バッジ: 「最新」または「データ更新あり」
- 「週次報告の下書きを含める」チェックボックス
- 「AI分析を生成」または「再生成」ボタン

主要業務CTAにはJPTレッドを使う既存方針を保ち、AI生成は補助操作として白背景＋パープルのアウトラインを使う。フォーカスリングはJPTブルーとする。

### 5.2 システム判定

- 基準日時
- 期限超過件数
- タスクID、タスク名、期限、超過日数
- 「期限超過はLaravelが日付とステータスから確定」の説明

`resolved`（確認待ち）は`closed`ではないため、期限を過ぎていれば期限超過として表示する。

### 5.3 AI生成結果

1. 現在の進捗要約
2. リスク一覧
   - 重要度: 高／中／低
   - リスク名
   - 根拠
   - 推奨対応
3. 次に確認すべき事項
   - 質問
   - 質問する理由
4. 週次報告下書き
   - チェックボックスが有効な生成要求でのみ表示
   - コピーボタンを表示
   - コピー後はライブリージョンで完了を通知

LLM出力は構造化JSONを通常のReactテキストとして描画し、`dangerouslySetInnerHTML`は使わない。

### 5.4 注意文

結果下部に「AI生成内容は判断支援であり、原データを確認して利用する」ことを明記する。週次報告には「現況から作成した下書きで、前週比較・今週実績を断定していない」ことを併記する。

## 6. UI状態

| 状態 | 結果表示 | 生成操作 | 利用者への説明 |
|---|---|---|---|
| 初期 | なし | 有効 | 分析内容と外部送信範囲を説明 |
| 生成中 | なし、または既存結果を保持 | 無効 | スピナー／スケルトン、`aria-busy=true` |
| 成功 | 最新結果 | 再生成可 | 生成日時、「最新」 |
| 古い結果 | 旧結果を保持 | 再生成可 | 関連データ更新後であることを警告 |
| 失敗 | 旧結果があれば保持 | 再試行可 | エラーを`role=alert`で表示 |
| 生成権限なし | 保存済み結果 | 無効 | 閲覧専用である理由を表示 |
| タスク0件 | なし | 無効 | 先にタスク登録が必要と説明 |
| 設定無効 | なし | 無効 | 管理者設定で機能が無効と説明 |

### 6.1 再生成失敗時の保持

再生成開始時に現在表示中の結果を消さない。失敗時は、旧結果の上にエラー通知を追加し、生成日時と鮮度表示を維持する。失敗した要求を空の結果として保存・置換してはならない。

### 6.2 二重送信防止

生成中はボタンと週次報告チェックボックスを無効化し、同一画面からの連続クリックを防ぐ。サーバー側でも別途重複実行を防止する。

### 6.3 「結果を確認」と「再生成」の区別

1回の生成操作につき、ブラウザでUUIDの`request_id`を1個発行する。

- ブラウザ側タイムアウト・接続切断など、サーバーで成功したか不明な場合:
  - エラー文は「結果を確認してください」とする。
  - CTAは「結果を確認」。
  - **同じ`request_id`**で照会し、無条件に新しい生成を開始しない。
- Laravelが`failed`を確定してエラーJSONを返した場合:
  - エラー文は失敗理由に対応した安全な固定文言とする。
  - CTAは「再生成」。
  - **新しいUUID**を発行して別の生成操作として送る。
- `AI_PROCESSING`の場合:
  - CTAは「結果を確認」。
  - 処理中の同じ`request_id`を維持する。

どの場合も保存済みの前回成功結果は消さない。静的HTMLの「失敗」は、Laravelが失敗を確定した後に旧結果を保持する状態を表す。

## 7. サンプルデータ

静的モックの共通案件は以下とする。

- 基準日時: 2026-09-14 10:00 JST
- 案件ID: 42
- 案件名: 社内申請ポータル改善
- ステータス: `approved`
- 予算: 1,000,000円
- 実績: 850,000円
- 予算消費率: 85%

| ID | タスク名 | ステータス | 進捗 | 期限 | 工数 | システム判定 |
|---:|---|---|---:|---|---|---|
| 201 | 要件整理 | `closed` | 100% | 2026-09-10 | 未設定 | 完了のため期限超過対象外 |
| 202 | 進捗API実装 | `in_progress` | 40% | 2026-09-11 | 見積3.0／実績4.5人日 | 3日超過 |
| 203 | 画面レビュー | `resolved` | 100% | 2026-09-12 | 未設定 | 2日超過 |
| 204 | 結合テスト | `open` | 0% | 2026-09-17 | 未設定 | 期限前・未割当 |

完了件数は`closed`のタスク201だけであるため、案件完了率は **1 ÷ 4 = 25%**。各タスクの進捗率の平均値ではない。

「タスク0件」デモ状態だけは同じ案件IDを使いながら、状態確認用フィクスチャとしてタスク一覧を0件へ置き換える。

## 8. 操作フロー

### 8.1 初回生成

1. 利用者が送信データの説明を確認する。
2. 必要に応じて週次報告チェックを切り替える。
3. 「AI分析を生成」を押す。
4. 生成中表示へ切り替え、操作を無効化する。
5. 成功したらシステム判定とAI生成結果を表示する。
6. 失敗したらインラインエラーと再試行ボタンを表示する。

### 8.2 古い結果の再生成

1. 関連データ更新後は「データ更新あり」を表示する。
2. 旧結果を読める状態のまま「再生成」を押せる。
3. 再生成失敗時も旧結果を残し、失敗通知だけを追加する。

### 8.3 週次報告コピー

1. 利用者が下書きを確認・修正判断する。
2. 「下書きをコピー」を押す。
3. 成功時は「コピーしました」を`aria-live=polite`で通知する。
4. Clipboard APIが使えない場合も選択コピーへフォールバックできる設計とする。

## 9. React統合時の画面契約

推奨コンポーネント:

```text
resources/js/Components/Projects/ProjectAiAnalysisCard.tsx
```

推奨Props:

```ts
interface ProjectAiAnalysisCardProps {
    projectId: number;
    initialAiAnalysis: ProjectAiAnalysis | null;
    aiGeneration: {
        allowed: boolean;
        unavailableReason:
            | 'forbidden'
            | 'not_approved'
            | 'not_configured'
            | 'no_tasks'
            | 'input_too_large'
            | null;
    };
    taskCount: number;
}
```

ページ初期表示では保存済みの最新結果を`initialAiAnalysis`、生成可否を`aiGeneration`としてInertia propsで受け取る。生成要求はJSONを返すエンドポイントのため、Inertia `router.post` ではなく型付きAxiosクライアントを利用する。フロントからタスク本文を送らず、URLの案件IDと、本文の`request_id`・週次報告の要否だけを送り、Laravel側で認可後に正規データを取得する。

## 10. レスポンシブ

- Desktop: AI要約とリスクを2カラム、次の確認事項と週次報告を下段に配置
- Tablet: 結果を1カラム化し、操作ボタンを折り返す
- Mobile: サイドバーを非表示、カード余白を縮小、ヘッダー操作を縦積み
- タスク表は横スクロール可能とし、情報を削除しない
- 状態切替用レビュー操作はモバイルでも横幅内に収める

## 11. アクセシビリティ

- すべてのボタン・チェックボックス・状態選択に明確なラベルを付ける
- キーボードだけで状態切替、生成、再生成、コピーを操作可能にする
- フォーカスリングを常に可視化する
- 生成中の領域へ`aria-busy=true`を設定する
- 成功・コピー通知は`aria-live=polite`
- 失敗通知は`role=alert`
- 重要度・鮮度・権限状態は色だけに依存せずテキストとアイコンを併用する
- `prefers-reduced-motion`ではスピナー以外の不要なアニメーションを停止する

## 12. 静的HTMLモックの範囲

`mockups/s04_project_ai_analysis.html` は次を満たす。

- 外部CDN、外部フォント、API通信を使わず単一ファイルで表示可能
- 冒頭に「未実装レビュー用サンプル」「通信なし」を表示
- 8状態をセレクトボックスで切替可能
- 生成ボタンはブラウザ内のデモ状態だけを変更
- 古い結果から再生成した場合は失敗デモとなり、旧結果を保持
- 週次報告チェックとコピー操作を確認可能
- 実サービスの認証、DB、LLM APIには一切接続しない
