# S-01 ログイン 方針

> **位置づけ**: 2026-10-03 に再設計。**B 案（2 カラム）を採用・実装済み**。
> **A 案（1 カラム）は改善候補**として本書とモックに残す。選考期間が終わったら A 案へ切り替える予定。

## 情報の優先度

ログイン画面を見る人（主にポートフォリオの閲覧者）がしたいことを、優先度順に並べた。

1. **ログインする** — メールアドレス・パスワード・ログインボタン（画面の主役）
2. **どのアカウントで入るか知る** — デモアカウントと共通パスワード（ログインの補助なのでフォームの近くに置く）
3. **アプリのことを知る** — このアプリについて / GitHub / Notion
4. **操作方法を調べる** — 操作マニュアル

## 両案に共通する仕様

- **ログインボタン**: 横幅いっぱいの赤（`jpt-red`）。「赤は最重要アクションだけ」のルールに沿う。`Components/ui/button` の default バリアントを使用
- **デモアカウントボタン**: フォームの上に代表 3 ロール（申請者 / 部門管理者 / 本部管理者）を並べる。押すとメールアドレスと共通パスワード `password` を入力する
- **パスワード表示**: ラベルを「パスワード：password」（`：password` は少し小さい文字）にする
- **ほかのテストユーザー**: 「ほかのテストユーザーを見る」で全ユーザーの表を開閉。メールアドレスを押すとそのアカウントを入力する
- **「パスワードを忘れた場合」リンク**: 表示しない（`/forgot-password` のルート自体は残っている）
- **リンク先**: このアプリについて `/manual?view=about`、GitHub `https://github.com/toutetu/ProjNexus`、Notion `https://lean-fifth-9ca.notion.site/ProjNexus-352421fa099e80138774cc647cc76b57`（公開 URL。`app.notion.com` は未ログインだと中継画面で止まるため使わない）、操作マニュアル `/manual`。すべて新しいタブで開く

## B 案（採用中）: 2 カラム

- **実装**: `resources/js/Pages/Auth/Login.tsx`（`GuestLayout` は使わず、画面内でレイアウトを組む）
- **左**: アプリ紹介（薄い青 `#EAF3FB`）。ロゴ、キャッチコピー、説明文、「このアプリについて」ボタン、GitHub / Notion の文字リンク、最下部に操作マニュアル（グレーの小さな文字）
- **右**: ログイン（デモアカウント → フォーム → 赤いログインボタン → ほかのテストユーザー）
- **スマホ**: ログインを先に、紹介を下に表示（`order-*` で入れ替え）
- **採用理由**: 選考期間中は、採用担当の方などに「このアプリについて」も目に入れてほしいため

## A 案（改善候補）: 1 カラム・ログイン最優先

- **モック**: `mockups/s01_login_option_a.html`（ブラウザで直接開ける）
- **構成**: 上にロゴ、中央にログインカード（中身は B 案の右カラムと同じ）、カードの外に「このアプリについて / GitHub / Notion」を横並びの青い文字リンク、その下に操作マニュアル（グレーの小さな文字）
- **良い点**: 迷わずログインボタンまでたどり着ける。今までのレイアウトからの変更が小さく、スマホでも見やすい

### A 案へ切り替える手順

1. `Login.tsx` を `GuestLayout`（ロゴ付きの 1 カラムレイアウト）で包む形に戻す
2. 右カラム（`{/* ログイン */}` の `<section>`）の中身をそのままカードの中身にする
3. 左カラム（`{/* アプリ紹介 */}` の `<section>`）はキャッチコピーと説明文を外し、リンクだけをカードの外へ移す（モックの「紹介リンク」部分）
4. ローカルで PC 幅とスマホ幅を確認する
